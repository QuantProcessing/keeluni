# 限流与连接

所有访问交易所的请求都经过 gateway 的限流层（`gateway/ratelimit`），这是 gateway 作为「唯一出口」的意义所在：同一交易所的额度只有一份，统一分配。

## 本地预算

每个交易所一个「每分钟单位数」的本地上限。这是本进程的运行上限，不是交易所全部配额的模型：

| 交易所 | 单位/分钟 | 依据 |
|---|---|---|
| Binance | 1200 | |
| Bybit | 1200 | |
| Hyperliquid | 1200 | 官方 REST 每 IP 每分钟 1200 权重；各接口成本按该权重表达 |
| Kraken Futures | 1200 | 官方 `/derivatives` 每 10 秒 500 成本单位（下单 10、查询 1–3）；下单/撤单成本记为 10 |
| Aster | 1200 | |
| OKX | 600 | |
| Bitget | 600 | |
| Gate | 600 | |
| Deribit | 600 | 新账户约每秒 20 个非撮合、5 个撮合请求；下单/撤单成本记为 10 |
| Gate CrossEx | 600 | 官方每用户每 10 秒下单/撤单 100、查询 200；**一个 Key 覆盖全部可达交易所，是一份预算** |
| Lighter | 300 | |
| Nado | 300 | |

每个请求的成本与所属接口来自 `internal/venuehttp` 的策略表。没有策略的请求直接被拒绝，保证每个新接口都被显式核算。

## 优先级

| 类别 | 规则 |
|---|---|
| 撤单 | 不受保留额度限制，可以用尽全部额度 |
| 下单与查询 | 保留五分之一的额度给撤单 |
| 后台常驻采集 | 只能使用窗口的前 25%；拿不到就跳过本轮，不排队 |

交易所的冷却（例如被限流后的封禁期）对所有请求都生效：优先级不能绕过 IP 封禁。

## 账户维度

除了交易所维度，每个账户（以凭证摘要作为 principal）还有自己的接口维度预算。这样同一交易所的多个账户不会因为一个账户的高频查询互相挤占；账户的路由重建或换 Key 时预算延续。

## 连接复用

- **公共行情**：同一 `(频道, 标的)` 在 gateway 内只开一个上游订阅，引用计数；最后一个订阅者离开后延迟 30 秒关闭，页面刷新不会反复开关交易所连接。
- **私有流**：每个账户一条（Binance U 本位的 USDT 与 USDC 共用一条；CrossEx 账户一条覆盖全部可达交易所）。
- **启动预热**：gateway 启动时为每个市场订阅一次盘口，提前建立公共 WebSocket 连接，避免第一个用户承担数秒的 TLS 握手。
- **慢消费者**：hub 推送时，跟不上的订阅者会丢消息而不是阻塞上游。所有保留型频道（盘口快照、持仓、余额）推送的都是完整状态，下一条消息即可修复。
