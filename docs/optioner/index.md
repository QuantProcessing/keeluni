# optioner 期权

期权应用：所有期权账户的**组合风险**，以及**多腿组合**的执行。与 hedger 一样只经 gateway 访问交易所；与 hedger 不同，它**没有数据库**。

## 为什么不需要数据库

hedger 必须积累交易所给不回来的历史（一组对冲的两条腿、资金费累计），所以有 PostgreSQL。期权的风险则完全是交易所的当前事实：持仓来自账户流，价格与 IV 来自期权链。执行记录在内存中保留一天，每条腿都带 clientOrderId，重启后交易所的持仓与挂单就是全部事实。

## 风险

每个标的一份报告，单位都是交易员下单时用的单位：

| 字段 | 含义 |
|---|---|
| Delta | 标的数量与美元。包含期权 Delta、同一标的的永续 / 现货（可关闭），以及**币本位权利金所持有的币** |
| Gamma 1% | 标的上涨 1% 时美元 Delta 的变化 |
| Vega | 所有到期日 IV 上升 1 个点的美元变化 |
| Theta | 每自然日的美元变化 |
| 市值 / 盈亏 | 期权按标记价；永续的市值是未实现盈亏，现货是名义价值 |

### 币本位期权的 Delta

卖出一个 BTC 币本位跨式，期权 Delta 在平值处接近 0，但收到的权利金是 BTC——账户多了这部分币。只看期权 Delta，以为美元敞口为零，实际上 BTC 下跌时会亏掉权利金的美元价值。报告把这部分计入（Deribit 称为溢价调整后的 Delta），用 `-size × premium / forward` 计算。

### 情景分析

标的变动（-30% 到 +30%）× IV 整体变动（-20 到 +20 个点）的完全重估网格，可选向后推移 1 天或 7 天（Theta 进入网格）。远期随标的同比例移动，保持各到期日的基差。

### 对冲 Delta

在选定账户上找该标的的线性永续（USDC 优先，其次 USDT），按步长取整得出把 Delta 压到零的市价单，并显示取整后的残余 Delta。发送前需要确认。

## 执行

一个执行是一组腿（1 到 8 条），每条腿是**独立的限价单**——范围内的交易所都没有原子的组合订单簿，所以组合可能部分成交，执行记录逐腿显示状态而不是假装原子。

- **定价**：明确价格，或按 `mark` / `mid` / `bid` / `ask` / `iv` 解析。按 IV 定价时用该到期日远期反算价格，币本位再换回币。
- **取整**：按适用的档位（含分档最小变动价位）对齐。买单向下、卖单向上（不多付）；IOC 反过来（朝成交方向）。
- **期权只用限价单**：期权盘口太薄，市价单会被吃穿；想立即成交就用对手价 IOC。永续 / 现货的对冲腿可以用市价单。
- **结果未知**：按 clientOrderId 查询，绝不重发；交易所能证明不存在才算未下单。
- **状态**：`working` → `done` / `partial`（有腿未成交，组合不完整）/ `failed` / `canceled`。

## 部署

```
optioner   :8083   OPTIONER_DATA_DIR（只存 token）  GATEWAY_URL  GATEWAY_TOKEN_FILE
trader     OPTIONER_URL  OPTIONER_TOKEN_FILE   → /api/options/*
```

去掉 trader 的 `OPTIONER_URL` 即不启用期权菜单。
