# hedger 对冲

hedger 是与 trader 平级的应用：把两个标的（可以在不同交易所，也可以在同一交易所）作为**一组**开仓、跟踪、平仓。它只通过 gateway 交易，状态存在自己的 PostgreSQL 库里；不部署 hedger 时 trader 照常运行。

```
browser ──cookie──> trader ──/api/hedge/*──bearer──> hedger ──bearer──> gateway ──> 交易所
                      └─────/api/gw/*────────────bearer──────────────> gateway
hedger ──> PostgreSQL（自己的库和角色）
```

## 概念

### 对冲组（group）

两条腿（leg 1、leg 2），每条腿 = **账户 + 标的 + 开仓方向**。两条腿**必须一多一空**：同向请求直接拒绝，现货腿只能做多。一组有自己的状态、比例（ratio）、失败策略、标签与备注。

### 腿的账户

标的永远是订单簿所在交易所的（`okx:perp:BTC-USDT-SWAP`），账户是「用谁的钱、走哪条通道」。一个账户能交易某条腿，当且仅当：

1. 账户已启用；
2. 账户的 `markets` 包含该标的的市场；
3. 账户的路由列表（`/v1/accounts/{id}/instruments`）包含该标的。

可以是该交易所的原生账户，也可以是能到达它的经纪账户（Gate CrossEx）。

- 每条腿的账户**必须由用户选**，没有默认值，也不会被自动换成别的账户；选择失效（换了标的、账户删除、路由消失）时清空。
- 两条腿可以用**同一个 CrossEx 账户**：同一个保证金池同时支撑两条腿，界面只显示一次可用保证金，所需保证金按两腿合计。

### 规则

每条腿按其账户的路由规则（tick、step、最小数量、最小金额）下单，并在开仓时快照到 `hedge_legs`。经纪账户的规则可能比交易所更细或更严。

### 比例（ratio）

`ratio` = 每 1 单位腿 1 对应的腿 2 数量。开仓时由 **hedger 根据两个标的计算**（前端不推断，`GET /v1/match` 提供给前端展示），之后的平仓、补腿都按它算。

- **同一底层资产**（BTC 对 BTC、PEPE 对 1000PEPE）：按数量匹配，比例由合约倍数决定（PEPE / 1000PEPE = 0.001）。
  - 识别的倍数前缀：`1000000`、`1M`、`10000`、`1000`，以及**仅 Hyperliquid** 的 `k`（`kPEPE`）。
  - 去掉前缀后必须以字母开头：`1INCH`、`10Y` 是名字，不是倍数。
- **不同底层资产**（BTC 对 ETH）：按开仓时的名义价值匹配，比例 = 腿 2 数量 / 腿 1 数量。

### 持仓永远是推导出来的

每条腿的持有量 = 开仓方向的成交 − 平仓方向的成交（来自订单的累计成交量与成交记录），**不单独存储**。重启、丢包、推送缺失都不会让 hedger 相信一个交易所并不持有的仓位。

### 动作（action）

`open` / `close` / `unwind`（含 trim）/ `rehedge`。同一组同一时间只有一个动作在执行，由数据库唯一索引保证。

## 状态

| 状态 | 界面 | 含义 |
|---|---|---|
| `opening` / `closing` | 开仓中 / 平仓中 | 有动作在执行 |
| `open` | 已对冲 | 两腿匹配（误差在两家步长允许范围内） |
| `broken` | **未对冲** | 两腿不匹配，有方向敞口，需要处理；也包括交易所持仓少于对冲记录 |
| `closed` | 已平仓 | 两腿都已平 |
| `failed` | 失败 | 开仓一笔都没成交 |

## 交易员看到的数字

| 数字 | 含义 |
|---|---|
| 入场 / 当前 / 出场价差 | 同底层时，腿 2 相对腿 1 的价差（bps）；入场按均价，当前按标记价，出场按现在平仓会成交的价格（买一 / 卖一） |
| 资金费率周期 | 按交易所给出的周期；Deribit 连续计息，按每小时折算，标为「连续计息」，不显示倒计时 |
| 净资金费率 APR | 空头腿收、多头腿付，按各自周期年化后相加，按单边名义价值计；另有 7 日均值（来自已结算资金费率） |
| 下次结算 | 最近一次结算的倒计时与预计收付金额 |
| 已收资金费 | 按每次结算的报价费率 × 持有量 × 价格估算（`hedge_funding`），精确数字以交易所账单为准 |
| 净盈亏 | 未实现 + 已实现 − 手续费 + 资金费 |
| 每条腿 | 持有量、均价、标记价、强平价与距离、杠杆、账户推送是否在线、该账户在该标的上的**交易所总持仓** |
| 成交质量 | 每笔市价单相对下单时盘口价的滑点 |

交易所按「账户 + 标的」合并仓位：同一账户上若还有对冲之外的仓位，交易所持仓会大于对冲持有量，界面会注明。

## 存储

PostgreSQL；表结构由程序内嵌的迁移脚本在启动时自动执行（`hedger_migrations` 记录版本，advisory lock 防止多个进程并发迁移）：

| 表 | 内容 |
|---|---|
| `hedge_groups` | 组：状态、比例、匹配方式、策略、标签、备注、问题（编码文本） |
| `hedge_legs` | 两条腿：账户（及是否经纪账户）、标的、方向、该账户路由的步长等规则（开仓时快照） |
| `hedge_actions` | 每次开 / 平 / 修复：模式、限价、目标数量、结果、错误（编码文本） |
| `hedge_orders` | 每笔订单：**先写后发**，clientOrderId 主键；状态、成交量、均价、错误（编码文本） |
| `hedge_fills` | 成交与手续费，按 (clientOrderId, fillId) 去重 |
| `hedge_events` | 每组的操作日志（编码文本） |
| `hedge_funding` | 每次结算的资金费估算 |

「编码文本」见[国际化](/dev/i18n#hedger-的消息)：以 JSON 保存编码、参数与英文渲染；改造之前写入的纯英文行照常显示。

每个应用一个库、一个角色：`hedger initdb` 用 PostgreSQL 超级用户创建 `hedger` 角色（随机密码）和 `hedger` 库，把连接串写入 `data/hedger/database.url`（0600）。数据库不可用时 hedger 不能开新仓，但 gateway 与 trader 不受影响。

## 已知限制

- 资金费收付是估算值，未读取交易所的资金费账单。
- 多个对冲组共用同一账户和标的时，对账按单个组比较：交易所持仓少于各组之和、但不少于每一组时不会报警。
- 现货腿只能做多（做空现货需要借币）。
- 限价动作不自动改价追单；需要时撤单后重新挂。
